# x-out: перемешивание групп в подписке

Локальная ветка `out/x-out` основана на upstream `8.0.0`. Расширение находится в
`backend/src/modules/subscription/x-out.ts`; `subscription.service.ts` вызывает его
непосредственно перед отправкой готовой подписки. Основной backend Remnawave менять
не требуется.

## Настройка

```yaml
proxy-groups:
  - name: 🇷🇺 Без рекламы
    type: fallback
    x-out:
      randomize: true
      mode: per-refresh
    remnawave:
      include-proxies: false
    proxies:
      - ♻️ 🇷🇺 Hades
      - ♻️ __[yt]Nlades
```

При каждом запросе подписки используется независимая перестановка Фишера — Йетса
с `crypto.randomInt`. Список может случайно остаться в прежнем порядке. Обработчик
меняет только порядок `proxies` в отмеченной группе: содержимое вложенных групп,
провайдеры, DNS, правила и учётные данные сохраняются. Поле `x-out` удаляется из
групп перед отправкой. Подписки без таких полей проходят побайтно без изменений.

Реализован только `per-refresh`; это также значение по умолчанию при отсутствии
`mode`. `randomize: false` удаляет маркер, сохраняя порядок. Неизвестный режим или
некорректные параметры сохраняют порядок и дают предупреждение без содержимого
подписки. Некорректный YAML и ответы больше 8 МиБ возвращаются без обработки.
Ограничено раскрытие YAML-алиасов.

В изменённом ответе удаляются устаревшие заголовки длины, кодирования и валидаторы;
добавляется `Cache-Control: private, no-store`. Прокси перед сервисом также должен
уважать этот заголовок и не кешировать подписки. При обходе subscription-page и
прямом запросе к панели расширение не применяется.

## Проверка и сборка

```sh
cd backend
npm ci
npm run typecheck
npm test
NODE_ENV=production npm run build
npm run trace
cd ..
docker build -f Dockerfile.x-out -t out/subscription-page:8.0.0-x-out.1 .
node scripts/smoke-x-out.cjs out/subscription-page:8.0.0-x-out.1
```

`Dockerfile.x-out` берёт frontend и runtime из официального образа, закреплённого
по digest, а сервер собирает из текущей ветки. Проверки типов и тесты обязательны
при сборке. UI не меняется; существующие mounts с оформлением страницы сохраняются.

## Обновления upstream

Форк: https://github.com/ckeiituk/subscription-page. Основная ветка — `out/x-out`,
`origin` указывает на форк, `upstream` — на `remnawave/subscription-page`.

Workflow `Update Remnawave upstream` проверяет стабильные Git-теги ежедневно
в 04:23 UTC (09:23 Екатеринбург); также доступен ручной запуск в Actions.
GitHub может задерживать запуск по расписанию. У Remnawave нет GitHub Releases
для subscriptions: версия определяется по наибольшему тегу `X.Y.Z` или `vX.Y.Z`,
без prerelease. Появление нового тега без готового Docker-образа даёт ошибку
проверки; следующий запуск повторит попытку.

Для новой версии workflow создаёт отдельную ветку `out/upstream-VERSION`, вливает
тег, обновляет версию и digest образа в `Dockerfile.x-out` и открывает PR. Существующие
PR и ручные исправления не перезаписываются. Закрытый PR считается отклонённым:
бот не открывает его заново. Если слияние конфликтует, оно отменяется, а draft PR
содержит только `.github/x-out-upstream-conflict.md` со списком файлов и инструкцией.
Проверки такого PR намеренно завершаются ошибкой, пока отчёт не удалён после
ручного разрешения конфликтов.

После создания PR явно запускается `Check x-out` на его ветке: тесты обновлятора,
TypeScript, тесты backend, сборка и проверка работающего контейнера. Автоматическое
слияние PR, публикация образов и установка на сервер не выполняются. После
успешных проверок нужно просмотреть diff, принять PR, собрать собственный образ с
новым точным тегом и отдельно обновить рабочий контейнер.

Для запуска автоматизации в форке включены Actions и разрешение «Allow GitHub
Actions to create and approve pull requests». Workflow использует встроенный
`GITHUB_TOKEN`, отдельный PAT не нужен. Обновлятору даны права на запись веток,
создание PR и запуск проверок; workflow проверок имеет только `contents: read`.
Унаследованные workflow публикации ограничены исходным репозиторием Remnawave.
Расписание работает только из default branch, поэтому `out/x-out` должна оставаться
основной веткой. В публичном репозитории GitHub отключает расписание после 60 дней
без активности — его тогда нужно снова включить в Actions.

Ограничения токена и расписаний описаны в [GitHub Docs](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows).

Для ручного обновления: создать ветку от `out/x-out`, выполнить
`git fetch upstream --tags` и `git merge VERSION`, обновить digest и label в
`Dockerfile.x-out`, затем выполнить проверки из раздела выше. При новых требованиях
upstream отдельно обновить Node builder и тестовые данные runtime-проверки.

Обновление официального `latest` не обновляет нашу сборку. В compose должен быть
указан собственный точный тег, а не `remnawave/subscription-page:latest`. Для локально
собранного образа используйте `pull_policy: never`; для собственного registry — его
адрес и опубликованный неизменяемый тег. Храните предыдущий образ для отката.

Для отката вернуть предыдущий тег и пересоздать только сервис subscription-page.
При откате на официальный образ сначала убрать `x-out` из шаблонов или учитывать,
что порядок перестанет перемешиваться.
